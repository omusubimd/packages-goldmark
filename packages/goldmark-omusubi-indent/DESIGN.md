# インデント拡張の設計・互換性

## 比較対象

- packages-unified: `4778af5aac9c67b9d36a4c89fa76864351e843b2`
- website: `c1b62965e69f8935078c4cc3c53434379990fc2a`
- Goldmark: v2.1.5

参照したのは micromark / remark の実装・README・14テストと、website の
`src/contents/pages/syntax/indent.md` です。仕様は全角スペースによる段落開始を、空行で段落を区切る記法と同等と説明しています。

## アーキテクチャ

ブロックパーサーで U+3000 を認識し、通常の `ast.Paragraph` を開きます。
印のない継続行、段落の終了、インライン構文、参照定義の収集は Goldmark に任せます。
印の後ろを新たなブロック開始として解析しないので、`　# title` は見出しになりません。
フェンス・HTML・インデントコードの中は既存パーサーが管理し、本文の全角スペースを保ちます。
UTF-8 の先頭バイトで呼ばれるパーサーなので、Open で U+3000 全体を確認します。

印だけの行は一時的なブロックノードとして閉じ、AST 変換で除去します。
空の paragraph として表現すると次の Setext 下線と干渉するため、paragraph にはしません。
通常の段落ノードを使うことで、外側のインライン拡張・ルビ・HTML 設定がそのまま有効になります。

新モジュールは Goldmark だけに依存します。ルビとの結合テストは独立した `integration` モジュールに置き、
公開モジュール同士に開発用の `replace` や未リリースの依存を追加しません。

## 確認済みの設計方針

2026-11-09 の仕様確認で、①は CommonMark の空行との同等性、②は Goldmark 標準の参照定義処理を使う方針を確認しました。

### 印だけの行と下線見出し

入力が `one\n　\n---` のとき、現在の unified 版は `<h2>one</h2>` を返します。
全角スペースによる段落開始は、CommonMark の空行による段落開始のエイリアスとして考えます。
この境界例は `one\n\n---` と同じく `<p>one</p>` と `<hr>` を返します。
空行なしの `one\n---` は Setext 見出しですが、空行を挟むと `---` は水平線です。
`===` の場合も前の段落とは切り離し、通常の段落本文として扱います。

| 選択肢 | 利点 | 影響 |
| --- | --- | --- |
| 現行 unified の境界動作を再現する | その入力の HTML を揃えられる | 区切り行を越えて前の段落が見出しになる特例が必要 |
| 印だけの行を段落の区切りにする（採用） | 「本文を生成せず前後を区切る」という README の説明に合い、Goldmark のブロック構造を保てる | 上の入力で unified と結果が異なる |

上の unified の出力は、確認済みの空行エイリアスという解釈との差として記録します。
引用内でも、印だけの行を空行に置き換えた標準 Goldmark の結果と比較します。

### 印の後ろの半角スペースと参照定義

入力が `　 [ref]: /url\n[ref]` のとき、unified 版は参照定義を本文として残します。
この実装は Goldmark 標準の段落変換を通すため、参照を定義し、後ろの `[ref]` をリンクにします。
印の直後が `[ref]` であれば、両方とも定義を認識します。

| 選択肢 | 利点 | 影響 |
| --- | --- | --- |
| unified に合わせて先頭の空白付き参照定義を抑制する | この境界例の構文互換性が上がる | Goldmark 標準の参照定義変換を部分的に置き換える必要がある |
| Goldmark の参照定義処理を使う（採用） | 他の段落と同じ Markdown 規則・ホスト設定を使える | 上の入力は unified と異なる |

本文の空白自体は保存します。差は参照定義の解釈であり、一般の本文から空白を削る変更ではありません。

## レンダラーと改行に由来する差

専用 HTML レンダラーを導入して他エンジンの整形に合わせることはせず、Goldmark の出力を使います。

- 生 HTML は Goldmark の既定では省略コメントになります。`html.WithUnsafe()` なら保持します。
  unified / micromark の既定では生 HTML をエスケープした文字列として出力します。
- tight list 内の隣接段落は、micromark が `onetwo`、Goldmark が `one\ntwo` と出す例があります。
  段落ノードと tight/loose 判定は各エンジンの既定のものです。
- 空の区切り行から micromark が追加する HTML の空行、空リスト項目の内部の改行は再現しません。
- Goldmark は通常 LF で HTML を出し、CRLF を LF に揃えます。CR 単独の行区切りは
  このバージョンの Goldmark 標準と同じ扱いなので、U+3000 構文を起動しません。
- 文書末尾の改行の有無だけは比較テストで正規化します。内部の差はすべて比較用データで明示します。

## 検証範囲と残る点

基本4例に加え、印の個数・空白・タブ・コード・HTML・参照定義・Setext・引用・リスト・改行を含む81例を
同じ unified 実装から生成し、意図した差だけを `goldmarkOutput` と分類で記録しました。
既存の入力の HTML と AST を標準 Goldmark と比較し、ソースの不変性・元のバイト位置・並行利用・ルビ併用も検証します。

完全な CommonMark 全例での差分検証や全拡張の組み合わせは行っていません。
書き戻し、CSS による表示上の字下げ、ルビの複数行対応はこの拡張の範囲外です。
